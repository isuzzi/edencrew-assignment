# Flutter 신입 개발자 과제

## 주식 앱 Flutter 과제

Flutter와 Figma 디자인을 기반으로 주식 관심종목, 종목 검색, 종목 상세 화면을 구현한 프로젝트입니다.

네이버 금융 데이터를 연동하여 실제 종목 및 시세 데이터를 표시하고, 관심 상태를 세 화면에서 공유하도록 구현했습니다.

---

## 실행 방법

### 개발 환경

- Flutter
- Dart SDK `^3.11.5`
- macOS
- iOS Simulator
- Chrome

### 실행

```bash
flutter pub get
flutter run
```

### 정적 분석

```bash
flutter analyze
```

### 확인 환경

- iOS Simulator

`flutter analyze` 실행 결과 문제없이 통과하는 것을 확인했습니다.

## 구현 범위

### 1. 관심 종목

- 관심 종목 목록 조회
- 종목명 / 종목코드 / 시장 표시
- 현재가 및 전일 대비 등락액 / 등락률 표시
- 상승 / 하락 / 보합 상태별 색상 처리
- 관심 종목 새로고침
- 관심 종목이 없는 경우 빈 상태 표시
- 현재가순 / 등락률순 / 가나다순 정렬
- 정렬 기준 변경 및 정렬 바텀시트
- 시세 조회 전 스켈레톤 상태

### 2. 종목 검색

- 종목 검색
- 검색어 입력 및 삭제
- 검색어와 일치하는 종목명 부분 하이라이트
- 검색 결과가 없는 경우 빈 상태 표시
- 관심 등록 / 해제
- 관심 상태에 따른 별 아이콘 변경
- 관심 등록 / 해제 토스트
- 검색 결과에서 종목 상세 화면으로 이동

### 3. 종목 상세

- 종목명 / 종목코드 / 시장 표시
- 현재가 및 전일 대비 등락 표시
- 관심 등록 / 해제
- `1개월 / 3개월 / 6개월 / 1년` 기간 선택
- 기간에 따른 차트 데이터 변경
- 캔들 차트
- 시가 / 고가 / 저가 / 거래량 / 시가총액 요약
- 일별 시세 표
- 일별 시세 페이지네이션
- 일별 시세 로딩 상태
- 일별 시세 오류 상태

### 4. 상태 동기화

관심 상태를 공통 상태로 관리하여 다음 화면에서 동일한 상태가 유지되도록 구현했습니다.

- 관심 화면
- 검색 화면
- 종목 상세 화면

검색 화면에서 관심 등록한 종목은 관심 목록에 즉시 반영되며, 상세 화면에서 관심 상태를 변경한 경우에도 이전 화면의 상태가 함께 변경됩니다.

### 디렉터리별 역할

#### `models/`

앱에서 사용하는 데이터 모델과 공통 상태 관리 로직을 관리합니다.

- `stock.dart`
  - 종목명, 종목코드, 시장, 현재가, 등락액, 등락률 및 상세 시세 정보를 관리합니다.
- `daily_price.dart`
  - 일별 시세 데이터를 모델링합니다.
- `naver_search_result.dart`
  - 종목 검색 API 응답을 앱에서 사용하는 형태로 변환하기 위한 모델입니다.
- `stock_store.dart`
  - `ChangeNotifier`를 기반으로 관심 종목 및 시세 데이터를 관리합니다.
  - API Service와 화면 사이에서 상태를 관리합니다.
  - 관심 종목 상태를 저장하고 불러오는 역할을 담당합니다.
  - 종목별 일별 시세 데이터를 페이지 단위로 관리합니다.

#### `screens/`

페이지 단위의 화면 구성과 화면 상태를 담당합니다.

- `main_screen.dart`
  - 관심 / 검색 화면의 기본 진입 및 네비게이션을 구성합니다.
- `watchlist_screen.dart`
  - 관심 종목 화면을 구성합니다.
- `search_screen.dart`
  - 검색 입력 및 검색 결과 화면을 구성합니다.
- `stock_detail.screen.dart`
  - 종목 상세 화면의 상태와 데이터 흐름을 관리합니다.
  - 선택한 기간에 따라 일별 시세 데이터를 조회하고 차트 및 표에 전달합니다.
  - 일별 시세 로딩 및 오류 상태를 관리합니다.

#### `services/`

외부 API와의 통신 및 데이터 조회를 담당합니다.

- `naver_api_service.dart`
  - 종목 검색
  - 종목 메타데이터
  - 현재 시세
  - 일별 시세
    등의 외부 데이터를 조회합니다.

#### `theme/`

Figma에서 제공된 디자인 기준을 코드에서 재사용할 수 있도록 색상 및 텍스트 스타일 등의 디자인 토큰을 관리합니다.

#### `widgets/`

화면에서 반복적으로 사용되거나 독립적인 역할을 가진 UI를 기능별로 분리했습니다.

- `search/`
  - 검색 입력창
  - 검색 초기 상태
  - 검색 결과 없음 상태
  - 검색 결과 목록
- `stock/`
  - 종목 상세 헤더
  - 기간 선택
  - 캔들 차트
  - 요약 정보
  - 일별 시세 표
  - 종목 리스트
- `watchlist/`
  - 관심 종목 헤더
  - 관심 종목 항목
  - 빈 상태
  - 정렬 바텀시트

Screen이 모든 UI 구현을 직접 담당하지 않고 화면 구성과 개별 UI 컴포넌트의 책임을 분리했습니다.

## 아키텍처 및 데이터 흐름

별도의 아키텍처 프레임워크를 적용하기보다는 프로젝트 규모에 맞춰 Screen / Widget / Store / Service / Model을 역할별로 분리했습니다.

### 데이터 흐름

```text
                    ┌──────────────────┐
                    │    Naver API     │
                    └────────┬─────────┘
                             │
                             ▼
                    ┌──────────────────┐
                    │ NaverApiService  │
                    └────────┬─────────┘
                             │
                             ▼
                    ┌──────────────────┐
                    │      Model       │
                    │ Stock /          │
                    │ DailyPrice /     │
                    │ SearchResult     │
                    └────────┬─────────┘
                             │
                             ▼
                    ┌──────────────────┐
                    │    StockStore    │
                    │  ChangeNotifier  │
                    └────────┬─────────┘
                             │
              ┌──────────────┼──────────────┐
              ▼              ▼              ▼
        WatchlistScreen  SearchScreen  StockDetailScreen
              │              │              │
              └──────────────┼──────────────┘
                             ▼
                           Widgets
```

### 역할 분리

| 구성    | 역할                                    |
| ------- | --------------------------------------- |
| Service | 외부 API 데이터 조회                    |
| Model   | API 및 앱에서 사용하는 데이터 구조 표현 |
| Store   | 화면 간 공유 상태 및 시세 데이터 관리   |
| Screen  | 페이지 단위 상태 및 화면 구성           |
| Widget  | 독립적인 UI 구성                        |

API 통신과 데이터 처리를 Screen에서 직접 담당하지 않도록 분리하여 UI 코드와 외부 API의 결합도를 낮추고, 여러 화면에서 동일한 상태를 사용할 수 있도록 구성했습니다.

## 상태 관리

`StockStore`에서 `ChangeNotifier`를 사용하여 관심 종목 상태와 시세 데이터를 공통으로 관리합니다.

관심 상태가 변경되면 `notifyListeners()`를 통해 이를 구독하는 화면이 갱신되도록 구성했습니다.

### 관심 종목 상태

관심 종목의 등록 / 해제 상태는 `StockStore`에서 관리하며, 다음 화면에서 동일한 상태를 사용합니다.

```text
WatchlistScreen
       │
       ├─────────────┐
       ▼             ▼
SearchScreen    StockDetailScreen
       │             │
       └──────┬──────┘
              ▼
         StockStore
              │
              ▼
     관심 상태 변경 / 저장
```

관심 상태는 로컬 저장소에도 저장하여 앱을 다시 실행한 이후에도 관심 종목을 복원할 수 있도록 구현했습니다.

### 일별 시세 데이터 관리

일별 시세는 종목과 페이지를 기준으로 캐시하여 동일한 페이지를 반복적으로 조회하는 상황을 줄이도록 구성했습니다.

```text
종목 코드
   │
   ├── 1페이지 → 일별 시세 목록
   ├── 2페이지 → 일별 시세 목록
   ├── 3페이지 → 일별 시세 목록
   └── ...
```

또한 종목별 마지막 페이지 정보를 별도로 관리하여 페이지네이션의 마지막 페이지를 처리할 수 있도록 했습니다.

## 네이버 데이터 연동

`NaverApiService`를 별도로 두어 네이버 금융 API와 앱 화면 사이의 데이터 조회 책임을 분리했습니다.

### 조회 데이터

- 종목 검색 결과
- 종목 기본 정보
- 현재 시세
- 일별 시세

화면에서는 API 응답을 직접 처리하기보다 Model과 `StockStore`를 통해 필요한 데이터를 전달받도록 구성했습니다.

## 종목 상세 데이터 처리

종목 상세 화면에서는 선택한 기간에 따라 필요한 일별 시세 데이터를 조회합니다.

```text
기간 선택
   │
   ▼
selectedPeriod 변경
   │
   ▼
StockStore에서 해당 기간 데이터 조회
   │
   ▼
dailyPrices 갱신
   │
   ├── StockPriceChart
   │
   └── StockDailyPriceTable
```

기간을 변경하면 해당 기간의 데이터를 다시 조회하고 차트와 일별 시세 표에 동일한 데이터가 반영되도록 구성했습니다.

일별 시세 조회 중에는 로딩 상태를 표시하고, 조회에 실패한 경우 오류 상태를 표시하도록 구현했습니다.

## 차트

종목 상세 화면의 차트는 일별 시세 데이터를 기반으로 캔들 차트를 표시합니다.

- 선택한 기간에 따라 차트 데이터 변경
- 시가 / 고가 / 저가 / 종가 데이터를 이용한 캔들 표시
- 상승 / 하락 방향에 따른 차트 색상 구분
- 차트와 주변 상세 정보의 세로 위치를 Figma 기준에 맞춰 조정

과제에서 차트 영역은 Figma와 완전히 동일한 내부 구현을 요구하기보다 데이터 표현과 주변 요소와의 배치를 기준으로 구현할 수 있도록 되어 있어, 차트 구현 방식은 프로젝트 구조에 맞춰 적용했습니다.

## 주요 구현 및 해결 사항

### 종목 변경에 따른 상세 데이터 갱신

종목 상세 화면에서 선택한 종목을 기준으로 API 데이터를 조회하도록 구성하여, 종목 변경 시 기존 종목의 데이터가 남아 있지 않도록 처리했습니다.

차트와 일별 시세 표 역시 현재 선택된 종목의 데이터를 사용하도록 연결했습니다.

### 기간 변경에 따른 데이터 갱신

`1개월 / 3개월 / 6개월 / 1년` 기간을 선택하면 선택된 기간을 기준으로 일별 시세 데이터를 다시 조회하고 차트와 표에 반영하도록 구현했습니다.

### 일별 시세 페이지네이션

네이버에서 제공하는 일별 시세의 마지막 페이지 정보를 확인하여 페이지네이션에 반영했습니다.

페이지별 데이터를 캐시하고 종목별 마지막 페이지를 관리하여 페이지 이동 시 데이터를 구분하도록 구성했습니다.

### 관심 상태 동기화

관심 등록 / 해제 로직을 `StockStore`에서 공통으로 관리하여 관심 화면, 검색 화면, 상세 화면에서 동일한 관심 상태를 사용할 수 있도록 구현했습니다.

### 관심 상태 영속화

관심 종목 상태를 로컬 저장소에 저장하고 앱 시작 시 저장된 상태를 불러와 복원하도록 구현했습니다.

### 시세 상태 처리

API 데이터를 불러오는 동안 로딩 상태를 표시하고, 일별 시세 조회에 실패한 경우 오류 상태를 표시하도록 구현했습니다.

### 등락 방향 및 색상

전일 대비 등락액과 등락률의 방향이 실제 가격 변화와 일치하도록 확인했으며, 상승 / 하락 / 보합 상태에 따라 화면의 색상이 올바르게 표시되도록 처리했습니다.

---

## 과제 진행 중 확인한 사항

- `flutter analyze` 통과
- 관심 / 검색 / 상세 화면 간 관심 상태 동기화 확인
- 실제 네이버 데이터를 이용한 종목 및 시세 표시 확인
- 종목 변경에 따른 차트 / 일별 시세 데이터 변경 확인
- 기간 변경에 따른 차트 / 일별 시세 데이터 변경 확인
- 일별 시세 페이지네이션 및 마지막 페이지 처리 확인
- 상승 / 하락 등락 방향 및 색상 확인
- 관심 종목 상태 저장 및 앱 재실행 후 복원 확인
- 검색 결과에서 관심 등록 / 해제 상태 확인
- 빈 상태 및 로딩 상태 확인

## 과제 2

과제 2에서는 Lucy Studio를 사용하여 `목표가 알림` 화면을 별도로 구현했습니다.

### 구현 내용

- 목표가 알림 빈 상태
- 목표가 등록 다이얼로그
- 종목명 / 목표가 입력
- 매수 / 매도 구분
- 등록한 목표가 목록 표시
- 목표가 천 단위 쉼표 표시
- 다이얼로그 열기 / 닫기
- 매수 / 매도에 따른 목표가 표시 색상

Lucy Studio의 Color Theme을 처음 설치 후에는 이용했으나 이후에 프로그램 실행 시 프로젝트에서 직접 불러오는 방식 및 figma import 적용이 되지 않아 Color Theme을 이용하지 못했습니다. 화면 구현에서는 과제 1에서 사용한 디자인 기준을 참고하여 작업했습니다.
